# Отзыв утёкших секретов — что и где сделать

История git **не переписывается** (решение владельца репозитория:
`6b0957a` остаётся как есть). Значит переписывание истории не отменит уже
случившуюся публикацию — единственный реальный способ закрыть утечку — это
**отозвать/сменить сами секреты** у провайдеров ниже. Действия ниже никак
не зависят от того, чистится git-история или нет — делать их нужно в любом
случае, и чем раньше, тем лучше.

Ни один реальный секрет **намеренно не приведён в этом файле** — только
названия полей и файлы, где он лежит, чтобы не плодить ещё одну копию
утечки в документации.

---

## 1. Telegram bot token

**Где лежит**: поле `bot_token` в `настройки 15.11.22.xml`, а также в
`messages.html` и `messages2.html` (переписка).

**Что сделать**:
1. Открыть чат с [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправить `/mybots` → выбрать бота из списка.
3. `Bot Settings` → `API Token` → `Revoke current token`.
4. BotFather выдаст новый токен — записать его **только** в свой `.env`
   (переменная `BOT_TOKEN`, см. `backend/.env.example`), не в git.
5. Перезапустить бота с новым токеном.

Старый токен после `Revoke` перестаёт работать немедленно — это самый
быстрый способ закрыть основную дыру.

## 2. SOCKS5-прокси (логин/пароль)

**Где лежит**: поле `proxy` (формат `ip:port:login:pass`) в
`настройки 15.11.22.xml`.

**Что сделать**:
1. Зайти в личный кабинет провайдера, у которого куплен этот прокси
   (проверьте письма на почте `lab767@gmail.com` от продавца прокси —
   там будет ссылка на кабинет и название сервиса).
2. В разделе со списком прокси/IP найти этот адрес (`85.143.202.209`),
   сменить пароль либо перевыпустить прокси заново.
3. Обновить новые данные в `.env` продовой машины.

Если сервис прокси не даёт сменить пароль без пересоздания — просто
купите/перевыпустите новый прокси и не используйте старый.

## 3. QIWI P2P secret key

**Где лежит**: поле `qiwi_secret_key` (длинная base64-строка) в
`настройки 15.11.22.xml`, также в `messages.html`, `messages2.html`,
`messages3.html`.

**Что сделать**:
1. Зайти на [qiwi.com](https://qiwi.com) под своей учётной записью.
2. Раздел управления P2P-ключами исторически находился по адресу
   `qiwi.com/p2p-admin/transfers/api` — если страница недоступна (QIWI
   заметно урезал/закрыл P2P API для многих аккаунтов), напишите в
   поддержку QIWI с просьбой отозвать API-ключ, привязанный к вашему
   мерчант-аккаунту (`payin_merchant_site_uid` виден в самом ключе).
3. Дополнительно проверьте историю операций и активные сессии в аккаунте
   QIWI — не появлялось ли постороннего доступа.

Даже если сам P2P-эндпоинт уже не работает, ключ стоит официально отозвать,
а не полагаться на то, что сервис сам всё выключил.

## 4. freelancehunt.com API-токен

**Где лежит**: поле `freelancehunt_token` в `настройки 15.11.22.xml`.

**Что сделать**:
1. Войти в аккаунт на [freelancehunt.com](https://freelancehunt.com).
2. В настройках личного кабинета найти раздел API / «Мои приложения» /
   интеграции.
3. Отозвать (revoke) текущий токен, выпустить новый, вписать в `.env`
   (`FREELANCEHUNT_TOKEN`).

## 5. superlance.pro — пароль

**Где лежит**: поля `login_superlance` / `pass_superlance` в
`настройки 15.11.22.xml`, также пароль текстом в `messages.html`,
`messages2.html`, `messages3.html`.

**Что сделать**:
1. Войти на [superlance.pro](https://superlance.pro).
2. В профиле сменить пароль на новый, ранее нигде не использовавшийся.
3. Логином указан `lab767@gmail.com` — **если этот же пароль используется
   ещё где-то (включая саму эту почту) — смените и там тоже**, и включите
   двухфакторную аутентификацию на почте, раз пароль от неё, по сути,
   был опубликован через этот сервис.

## 6. Google Apps Script web app URL

**Где лежит**: поле `web_app_url` в `настройки 15.11.22.xml`
(`script.google.com/macros/s/…/exec`), также в `messages.html` и
`messages3.html`.

**Что сделать**:
1. Открыть [script.google.com](https://script.google.com), найти проект
   этого веб-приложения (по названию бота/таблицы, к которой оно пишет).
2. `Deploy` → `Manage deployments` → создать **новый** деплой (это выдаёт
   новый URL, старый перестаёт быть валидным) либо `Edit` текущего
   деплоя и сузить `Who has access` (например, только с OAuth, а не
   «Anyone»).
3. Вписать новый URL в `.env` (`web_app_url`/аналог), если функциональность
   ещё нужна.

## 7. token_webhook (webhook.site)

**Где лежит**: поле `token_webhook` в `настройки 15.11.22.xml`.

**Что сделать**: это отладочный инструмент — просто зайти на
[webhook.site](https://webhook.site), получить новый уникальный URL/токен
и, если он больше не нужен в проде, вообще убрать `use_webhook` из
конфига.

## 8. Личная переписка (messages.html, messages2.html, messages3.html, messages4.html)

Эти файлы — экспорт переписки (похоже, с подрядчиком, который разрабатывал
бота), и в них **текстом продублированы почти все секреты выше**, плюс
могут быть личные детали, не предназначенные для публичного репозитория.
Рекомендация: если репозиторий публичный — сделать его приватным, либо
удалить эти 4 файла из репозитория обычным коммитом (без переписывания
истории — этого пока делать не будем по вашему решению).
