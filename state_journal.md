# state_journal.md — журнал состояний

Обязателен к обновлению **в конце каждой итерации** (не в начале — записывай
то, что реально произошло, а не план). Защита от галлюцинаций и зацикливания:
следующая сессия/итерация начинается с чтения последней записи, а не с
угадывания состояния проекта заново.

Правила (см. AUTONOMY_PROTOCOL.md §4 «Управление состоянием»):

- Каждая запись — новый блок сверху не добавляется, добавляется **снизу**
  (журнал читается сверху вниз в хронологическом порядке).
- Запись пишется **после** прохождения `validation_protocol.md` для
  завершённых пунктов — недоделанный/непроверенный шаг помечается в
  «Нерешённые проблемы», а не выдаётся за «Выполнено».
- Один блок = одна итерация (не один коммит — итерация может быть крупнее).
- Формат ниже — обязательные поля, порядок фиксирован.

## Формат записи

```
## [YYYY-MM-DD HH:MM UTC] Итерация N

**Фаза**: <из ТЗ/бэклога, например "Backend port" / "Autonomy scaffolding">
**Выполнено**: <конкретный пункт бэклога/задачи, который закрыт в этой итерации>
**Validation**: <pass/fail по validation_protocol.md — конкретные шаги>
**Нерешённые проблемы**: <явно; "нет" если правда нет>
**Следующий шаг**: <что делать следующей итерации, максимально конкретно>
```
