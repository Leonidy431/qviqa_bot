# CLAUDE.md — qviqa_bot

Инструкции для Claude Code (и любого агента) в этой репе.

## Обязательная инженерная политика — `.clauderc`

Файл [`.clauderc`](./.clauderc) содержит 99 жёстких, безкомпромиссных правил
проекта (архитектура, code review, тестирование/coverage 95%+, безопасность,
производительность, инженерные процессы). **Это не рекомендации — это
обязательные требования к любому изменению кода в этом репозитории.**
Прочитай `.clauderc` в начале любой сессии, где предстоит писать, ревьюить
или мержить код, и следуй ему как части системного промпта.

Главный закон файла (правило 99): код, не покрытый тестами на 95%+, с
архитектурными слепыми зонами или расходящийся с ТЗ — не имеет права
находиться в продакшене.

## Автономный протокол работы

Помимо `.clauderc` (инженерная политика) действует вторая ось правил —
как агент ведёт себя между итерациями (память, самопроверка, фильтрация
контекста). Разбор и полный список 99 правил — [`AUTONOMY_PROTOCOL.md`](./AUTONOMY_PROTOCOL.md).
Рабочие артефакты:

- [`state_journal.md`](./state_journal.md) — журнал состояний. **Читать в
  начале** нетривиальной сессии (что уже сделано, что не решено). **Обновлять
  в конце** каждой итерации — но только после того, как пройден
  `validation_protocol.md`; недоделанное фиксируется как «Нерешённые
  проблемы», а не выдаётся за «Выполнено».
- [`validation_protocol.md`](./validation_protocol.md) — жёсткий чек-лист
  (тесты + coverage ≥95%, `ruff check`/`ruff format --check`, сборка и
  healthcheck Docker, проверка на утёкшие секреты в diff, регенерация
  `context_map.json` при изменении импортов). Следующая задача бэклога не
  начинается, пока текущая не прошла протокол.
- [`.claudeignore`](./.claudeignore) — что агент не должен читать
  (venv/кэши/бинарники/дампы БД/оригинальные BAS-экспорты с секретами).
- [`context_map.json`](./context_map.json) — граф импортов `backend/app/*`,
  генерируется скриптом `tools/gen_context_map.py` (не редактировать руками
  — устареет на первом же коммите; регенерировать, когда меняются импорты).

### ⚠️ Мета-правило — делегирование сомнений (выше приоритетом, чем любое
### отдельное правило `.clauderc`)

**Если внутренняя оценка вероятности успешного выполнения задачи ниже
90% — СТОП. Не писать код. Задать РОВНО ОДИН точный, изолированный вопрос,
проясняющий именно слепую зону**, а не пять расплывчатых уточнений.
Автономия без этого тормоза — саморазрушение: агент либо зависает в цикле
неудачных попыток, либо тихо доставляет неверный результат уверенным тоном.

Живой пример применения в этом репозитории: вместо того чтобы по своей
оценке переписать git-историю и сделать force-push в `main` (необратимо,
ломает открытый PR и любые существующие клоны/форки), был задан один
точный вопрос — и решение осталось за владельцем репозитория (см.
раздел «Безопасность: секреты в истории git» ниже).

## Безопасность: секреты в истории git

Исходный коммит `6b0957a` («Add files via upload») на `main` содержит
файлы-экспорты BAS (`настройки 15.11.22.xml`, `messages*.html`) с **живыми
секретами в открытом виде**: токен Telegram-бота, логин/пароль SOCKS5-прокси,
секретный ключ QIWI P2P, токен freelancehunt.com, пароль superlance.pro,
URL Google Apps Script, токен webhook.site. Эти файлы не используются
портированным бекендом и не должны присутствовать в репозитории.

**Решение владельца репозитория (2026-07-30): git-историю не переписывать.**
Секреты остаются доступны через `git log`/GitHub у коммита `6b0957a` и его
потомков. Вместо этого владелец отзывает сами секреты у провайдеров —
это единственное, что реально закрывает утечку (переписывание истории не
отменяет уже случившуюся публикацию). Пошаговая инструкция со ссылками —
[`SECRETS_REVOCATION.md`](./SECRETS_REVOCATION.md). Если решение изменится —
`git filter-repo` для полной зачистки истории уже проверен в этой сессии.
